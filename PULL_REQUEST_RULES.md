# Pull Request Rules

- `main` and `dev` are protected branches.
- Direct pushes, force-pushes, and branch deletion are disabled.
- Every change requires a pull request and at least one approving review.
- A new push invalidates stale approvals and requires approval of the latest push.
- All review conversations must be resolved before merge.
- Keep PRs focused and link the relevant brief, PRD, story, ADR, contract, or issue.
- Describe tests, migrations, observability, security impact, rollback, and known failure modes.
- Use squash merge for short-lived branches unless a documented exception applies.
