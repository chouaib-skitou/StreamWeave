# Issues

Use this directory for issue briefs and decision-ready problem statements that are not yet implementation stories. Keep secrets, credentials, and vulnerability details out of public issues; use the private security reporting path for security concerns.

Issue titles follow the same English Conventional Commit format as commits:

```text
<type>(<scope>): <imperative description>
```

Examples: `feat(orders): Add customer cancellation flow`, `fix(inventory): Make reservation release idempotent`, and `docs(architecture): Explain Saga compensation policy`.

Every issue should state context, desired outcome, acceptance criteria, affected services/contracts/data, failure and security considerations, test plan, out-of-scope behavior, and references.
